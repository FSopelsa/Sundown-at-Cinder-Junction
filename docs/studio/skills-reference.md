# Useful Project Skills

Only skills that are installed and useful to Sundown’s current development
style are listed here. This is a menu, not required ceremony.

| Skill | Use it when | Expected output |
| --- | --- | --- |
| `$project-stage-detect` | deciding what is genuinely playable or what to build next | evidence-backed status and a few practical milestones |
| `$asset-audit` | admitting or changing runtime models | GLB, Blender, manifest, provenance, pivot, and browser-fit review |
| `$three-webgl-game` | changing the Three.js scene, input, or renderer boundary | simulation-safe Three.js implementation guidance |
| `$web-3d-asset-pipeline` | exporting or optimising Blender/GLB assets | pivot, material, GLB, and runtime validation checklist |
| `$build-3d-game-rooms` | planning rooms, modular kits, doors, or functional Blender reviews | room brief and Function/Form/Runtime review gates |
| `$game-playtest` | validating the browser build or HUD with a real player path | reproducible smoke-test evidence |
| `$playtest-report` | converting real player notes into decisions | concise, actionable findings |

The first two are project-local skills; the others are optional focused tools.
Avoid broad team orchestration, sprint templates, live-operations material, or
engine-specific guides unless the project later has a real need for them.
